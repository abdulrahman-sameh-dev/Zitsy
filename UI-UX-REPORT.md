# Zitsy UI/UX Overhaul — Final Report

Date: 2026-10-08
Scope: visual identity, page layout and copy for the Zitsy storefront. Backend/auth/cart/checkout/orders/PayPal/Printify/tracking/email architecture untouched.

## 1. Baseline (before changes)

- `pnpm typecheck` ✅ · `pnpm lint` ✅ · `pnpm test` ✅ 324/324 (31 files)
- E2E invariants confirmed (see `e2e/`): footer link labels "Track Order" → `/track-order`, "Contact Us" → `/contact`; tracking placeholders `ZS-XXXXXXXX` / `you@example.com`, "Find my order", "No account needed.", generic not-found copy, step "Order confirmed", destination + Total pair; contact labels/bubbles; no "Sign in" link on order-status pages.
- Real catalog facts (inspected DB): 25 visible products, 720 available variants, 1304 Printify images, GBP currency, all products have descriptions. Derived categories: T-Shirts (6), Hoodies (4), Tote Bags (4), Sweatshirts (4), Accessories (2), Mugs (1), Stickers (1), Backpacks (1), Sublimation (1), Hats (1). No candles category exists — homepage copy no longer claims one.

## 2. Brand identity and design system

- Brand scale: signal-orange `brand-600 #c8471e` / `brand-700 #a33817`; warm neutrals — canvas `#f6f4ef`, ink `#141412`, line `#e3e0d8`, muted `#6b6a63`; matching dark-surface tokens for the footer band.
- Typography: `Fraunces` (600/700) as display font (`--font-display`) alongside Geist; accessible smooth-scroll (`data-scroll-behavior="smooth"`).
- Component classes in `globals.css`: `.btn-primary`, `.btn-secondary`, `.chip`, `.chip-active`, `.prose-doc`; reduced-motion support.
- Assets generated by `scripts/generate-brand-assets.py`: `src/app/icon.png`, `src/app/apple-icon.png`, `public/favicon.ico`, `public/og.png` (1200×630). Boilerplate `public/*.svg` removed. OG/Twitter/applicationName metadata added to the root layout.

## 3. Storefront changes

- **Header**: brand logo, Home/Shop nav with active states (`nav-link.tsx`), desktop search form → `/search`, mobile search icon, "Track order" link, cart badge. **Footer**: dark ink band with Shop/Help/Company columns; e2e link names preserved.
- **Homepage**: real-product hero (actual featured image, category + "From £X" chip, factual copy), featured loader, category grid, value band, dark trust strip.
- **Discovery**: `searchVisibleProducts()` + `/search` (noindex, empty/no-results states, category chips); `/shop` gains sort (price-asc / price-desc / title), result counts, chip styles, no-results state.
- **PDP**: derived-category chip on cards; add-to-cart success with View cart / Continue shopping; "Printed to order" block with Shipping/Returns/Sizing links; Home breadcrumb node; "You may also like" (same category, max 4); loading skeleton.
- **Cart / checkout / tracking**: cart empty state with logo and tracking CTA; "Shipping and any applicable charges are confirmed at checkout." note; cart page metadata + noindex; checkout subtitle + clearer empty/attention states; checkout/success "What happens next" block and prominent Track your order (paid) / Continue shopping (pending) CTAs; tracking timeline connector rails + larger step indicators.
- **Policies & support pages**: shared `InfoPage` shell + `about`, `shipping`, `returns`, `sizing`, `privacy`, `terms` (honest content; no invented timelines/guarantees). `sitemap.ts` extended with these pages.

## 4. Incidental fixes

- `.env` contained a stray shell command appended as a duplicate `DATABASE_URL` (`…' pnpm prisma migrate deploy`). The value overrode the valid localhost URL and broke `pnpm build` (env validation). Duplicate removed; only the valid `postgresql://…@localhost:5432/zitsy_store` line remains.
- `e2e/contact.spec.ts` built a malformed customer email (missing `@`), so the server's Zod email validation always returned "Please enter a valid email address." Fixture repaired to `e2e-customer-<ts>@zitsu.darkhub.dev`; the test's assertions (store + customer emails, reply-to, subjects) are unchanged.

## 6. Known limitations / follow-ups

- `privacy` and `terms` pages are well-structured starting points; have a solicitor/legal reviewer sign off before launch.
- Vercel env gaps from the earlier production-readiness audit remain (this work did not deploy); the user runs `prisma migrate deploy` on the production DB themselves — verification of `_prisma_migrations`/tables is still pending.
- No candles category exists in the catalog; category-focused marketing copy must be re-derived if the catalogue changes.
- `sharp` is present only as a transitive dependency; asset generation uses PIL + Liberation fonts.
